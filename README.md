## Connected work

- **Linked tasks.** Create tasks from selected note text or checklist items, with source quotes, duplicate detection, and progress beside the note.
- **Work rooms.** Pin a project, focus task, notes, and canvas. Save a checkpoint with your next step, then resume the view and canvas position.
- **Relationships and reviews.** Connect items with **depends on**, **supports**, **contradicts**, or **was decided because of**. See which work may be affected by a change and mark reviewed connections.

## Templates

**15 starting points**, searchable by category:

| Work & learning                                                       | Everyday & wellbeing                                                                     | Creative & reference                              |
| --------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- | ------------------------------------------------- |
| Project brief · Weekly plan · Decision record · Study notes · Meeting | Daily journal · Habit tracker · Workout log · Meal plan · Personal budget · Trip planner | Worldbuilding · Character · Research · Blank note |

**Your own library:** open **My task templates** in the task editor or **My note templates** when creating a note or from its More menu. Reuse opens an editable task or a note creation form with a suggested unique title; review it before saving. Templates keep reusable content and checklist structure, omitting assignments, schedules, project links, history, and private attachments. Your library follows your account across its workspaces; guest templates stay in a separate local library.

## Accounts and collaboration

Register with an **email address, username, and ProjectAnvil password**; sign in with your **username and password**.

**Account security:** verify your email, change or reset your password, inspect signed-in browser sessions, and revoke access on other browsers. Local verification/recovery links stay in a private outbox on this PC; no email is sent. Password resets end existing sessions. See [account recovery](docs/LOCAL_SETUP.md#account-security-and-recovery).

**Access modes:** local mode retains the separate guest workspace and accepts loopback addresses only. A separately configured online mode requires approved, verified accounts and has no shared guest workspace. It stays unavailable until its HTTPS address, email service, secrets, and database migrations are prepared. This does not publish the app.

Each account has a private personal workspace. Team owners and admins invite registered users by username; access begins after acceptance. Viewers read available work, Editors make changes, and Admins manage members and project permissions. Owners can appoint Admins and transfer ownership to an accepted teammate. Projects start shared and can be restricted to selected members; workspace Viewers remain read-only. **Work rooms and checkpoints remain personal**, including inside a team workspace. Assigning a task or adding a person label does not grant access.

New workspaces start empty. Guest work stays separate from account and team workspaces.

## Developer setup

Requires **Node.js 22.13+** and npm. Clone or download the repository, open its folder, then run:

```sh
npm run install:ci
node scripts/start-local.mjs
```

Open **http://127.0.0.1:5173**. On Windows, **Start ProjectAnvil.cmd** provides the same startup flow. The launcher builds the installable app when needed and reuses a current build. Keep the console running for account access and synchronization; press **Ctrl+C** to stop. Explicitly saved offline work can remain available while the server is stopped.

**The current version runs locally on one computer.** Accounts and team workspaces do not enable remote access; mobile layouts are available when the app is served in a reachable environment. Initial dependency installation requires internet access.

For storage, backup, restore, and troubleshooting, see the [local setup guide](docs/LOCAL_SETUP.md). For publishing the source from VS Code, see [GitHub setup](GITHUB.md).

## Current limitations

- Projects can have restricted access inside a team workspace. Moving projects between workspaces is not implemented.
- Simultaneous editing applies to Markdown after each editor chooses **Edit together**; other fields use conflict checks. Offline copies need an initial connection and trusted browser storage. Reconnect to verify current access and synchronize; account changes, uploads, archived recovery, and folder transfers need the local server.
- Markdown folder transfers are manual. Automatic synchronization with an external folder is not implemented. Folder/ZIP import creates new notes; tasks, accounts, and histories use the other backup formats.
- Notifications and mentions are in-app. Account verification and recovery use local links; external email delivery, operating-system push, Google sign-in, and invitation emails are not configured.
- Reminders are in-app. Delivery needs the app open; snoozes and dismissals are browser preferences. Recurrence advances on completion rather than creating a backlog while the app is closed. See [planning behavior](docs/LOCAL_SETUP.md#project-planning-recurring-tasks-and-reminders) for time-zone and recovery details.
- Brainstorm voting is visible to the workspace, with one shared guest identity in guest mode. JSON import retains current votes for matching ideas and clears votes on new imported ideas; complete local backups preserve the full vote state. See [connected thinking](docs/LOCAL_SETUP.md#connected-thinking) for details.
- Workspace JSON excludes permissions, memberships, activity, watches, notifications, shared editing sessions, Trash, personal templates, archived note history, personal rooms, uploaded files, and accounts. Complete backups preserve confirmed local data; browser offline copies and queued or unsaved edits must be synchronized or downloaded separately. Importing resets relationship review markers and invalidates older Trash restores. Trash has no automatic expiry. See [backup options and storage limits](docs/LOCAL_SETUP.md#data-and-backups).

## Development

Built with **React, TypeScript, Vinext/Vite, Better Auth, Yjs, and local D1/R2 emulation**.

Use `npm run dev` for development with live source updates. Installable/offline startup uses the normal launcher or `npm run build` followed by `npm start`; development mode does not register the app cache.

Interface changes follow the [UI and UX standard](docs/UI_STANDARDS.md), including readability, navigation, accessibility, all five themes, and responsive review.

See the [agreed roadmap](docs/ROADMAP.md) for completed work, upcoming phases, and the future hosting checklist. The app remains local until online deployment is explicitly approved.

```sh
npm run check
npm run test:browser
npm run test:performance
```

Repeatable browser checks use two separate accounts in a disposable local installation. Performance profiles populate private and shared workspaces with up to 40 projects, 1,000 tasks, and 200 notes each. See [testing and measurements](docs/TESTING.md) for browser setup, reports, and safe reruns.

The [capacity review](docs/PERFORMANCE.md) records measured behavior and remaining work for larger teams. The [project structure guide](docs/ARCHITECTURE.md) explains feature ownership, data boundaries, and where new code belongs.

Note browsing supports combined filters, matching counts, and **Clear note filters** without leaving the current project or note. Note details open on demand, giving writing more space. Workspace settings groups everyday controls first, with Data & offline and People & access available when needed. Feature modules separate tasks, dashboard, settings, notes, graph, and canvas responsibilities; unused starter components and packages are removed.

Optional screens and technical formatting load when used. Failed screen loading offers **Retry opening** without reloading the workspace; unavailable formatting keeps readable source. Collections reuse search/property indexes and save property edits with revision checks. The app retains math, syntax colors, diagrams, and its existing planning tools while removing unused connector scaffolding and a redundant framework installation. Use `npm run size:report` to review the [size measurements](docs/PERFORMANCE.md#size-and-maintenance-review).
